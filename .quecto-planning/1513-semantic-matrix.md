## Applicability exclusions

Permissions, model/provider choice, workflow template identity, binary payload encoding, and protocol compatibility negotiation are irrelevant: this feature observes existing text transcript history through one parent-owned child registry. Concurrency matters only at the compute/delivery commit boundary and child append/reload interaction described above.

## Frozen clarifications after counterexample review

- **Truncation:** report shaping never splits cursor ownership ambiguously. The committed cursor is the highest fully represented message ordinal. If a single message is text-truncated, its envelope is fully delivered with `truncated: true` and original length metadata, so that ordinal may commit; later messages omitted by the cap remain unread for the next default call. No selected-but-omitted ordinal commits.
- **Delivery seam:** child UDS success and native tool return are preparation only. Add a narrow domain-port acknowledgment: after the parent agent loop appends the non-error tool result to both conversation and run ledger, `ToolExecutor::result_delivered(tool_name, arguments, result)` delegates to the invoked tool (default no-op for stateless tools). `AgentCmdTool` correlates the prepared report result and atomically commits its delivered ordinal to the resolved UUID-keyed registry entry; error results and failures before the callback do not commit. Each newly prepared report and each delivered default-report failure envelope first clears any stale pending ordinal, so an unchanged/error-equivalent retry cannot commit a boundary from a failed earlier delivery. The callback is invoked only after both appends, and duplicate callbacks apply monotonic `max`, so they are harmless. Tests inject failure between execute and append and verify retry/stale-pending cleanup. Parent session persistence then snapshots that committed registry ordinal with the same save that persists the appended tool result.
- **Response shape:** default changed output is `{ "messages": [...], "truncated": <bool> }`; `truncated` means additional unread messages remain or a delivered message content was summarized. Each message retains the established history message object shape plus durable `ordinal`. Default unchanged is exactly `{ "unchanged": true }`. First contact with no finalized assistant response is unchanged. No paging cursor fields ride report mode.
- **First response:** “latest assistant response” means the finalized assistant message with the greatest durable transcript ordinal. Tool calls/results earlier in that turn are excluded. First contact with unread non-assistant messages but no finalized assistant is exact unchanged and must not advance the cursor. A streaming/incomplete assistant value is not finalized and cannot commit; busy snapshots expose only the last committed transcript snapshot and are cursor-neutral until the normal parent tool-result commit seam.
- **Mode selection/legacy malformed values:** validate the raw `agent_cmd` object before building a command: present non-null `count` must be a non-negative integer fitting `usize`, and present non-null `before` must be a string; wrong types/negative/overflow return the existing addressable argument error and never enter report mode. Only both validated/deserialized options being `None` selects report mode. Legacy `count:0`, empty/invalid `before`, and paging behavior remain frozen. JSON `null` behaves as absent under the existing protocol and therefore selects report mode when both are null/absent; tests pin this explicitly.
- **Internal callers:** audit every no-argument child-history consumer. TUI attach/backfill/connect snapshots remain explicit history/snapshot surfaces and must request/use a count or dedicated builder; only parent operational observation adopts report mode.
- **Lineage and scope:** the cursor is stored on the UUID-keyed calling-parent registry entry and persisted with that same `agent_uuid`/child session key. Reusing a display name creates a fresh UUID/cursor. Ambiguous aliases are rejected before read/commit. For descendants routed through an ancestor, the top parent must not invoke downstream report mode (which would consume the ancestor's cursor). It forwards an internal explicit history request carrying the top parent's committed durable ordinal; the descendant returns a cursor-neutral ordinal projection, and only the top parent's post-append acknowledgment commits its local target UUID entry. This internal field is UDS-only, omitted from model-facing `agent_cmd`, and direct/routed/historical transcript adapters share the same report shaper. `*` is never a valid message target.
- **Pending tails/history:** explicit paging between report calls stays neutral even when it displays unread/omitted report ordinals. It cannot acknowledge them. Parent restore preserves the pending boundary through the persisted committed ordinal. If a parent-delivered child history mutation is confirmed successful and removes or rewinds the transcript (`clear_history` in current `agent_cmd`; any future exposed rewind/truncate command must opt into the same behavior), the parent clears both committed and pending report cursors for that child because vanished unread history is no longer recoverable through the child history API; subsequent post-mutation assistant output is reported from the fresh transcript instead of being suppressed by a stale ordinal. Rejected/failed destructive commands, including UDS envelopes with `success:false`, do not clear cursors.
- **Output cap:** use the repository’s deterministic four-bytes-per-token estimate (about 3.2 KiB for ~800 tokens), UTF-8 safely, and test both exact-boundary and over-boundary values.
- **Success metric:** cohort re-profiling remains deferred, but the PR records the expected follow-up and audits no-arg callers to avoid invalidating the reduction.

## Required high-risk tests added by final verification

1. Routed descendant: top parent reads through ancestor; ancestor cursor stays untouched; top parent's resolved target cursor commits only after top-parent delivery acknowledgment.
2. Persistence transaction: inject failure at save/restore boundaries and prove parent tool-result conversation state and persisted registry ordinal cannot restore in a divergent state; retry returns any result not durably acknowledged.
3. Paging argument table: `count:-1`, integer overflow, fractional/string/object count, non-string `before`, nulls, `count:0`, empty and unknown `before`; malformed inputs error without report-mode cursor movement, while legacy-valid/null behavior stays pinned.
