Container-only shared swarm coordination (large content in artifacts; never edit the store; an ack is not work done). Which container: the container the coordinator was spawned into (the host master names its container_config); the coordinator spawns workers with container omitted. Only the isolated-PID adapter (scripts/container-runtime/docker) can host a swarm; host-local reference scripts cannot host a swarm, nor can the host. Never set workflow, workflow_guards or workflow_spec on worker launches. First op=create a run: goal, constraints (optional), criteria [{id,kind:command|review,description}], member_limit 1–25 incl. coordinator (idle and reserved members count), deadline_in_seconds ≤7 days; then spawn a fixed pool. No nested containers to reset the cap.
Board ops: each is one call, {"op":"<name>", ...named fields}, answering the op's JSON (null for none). They need a running run within its deadline. Example: {"op":"claim","task_id":3} answers the task with its claim token. Any member: task(task_id), tasks(offset,limit), file_owners(offset,limit), task_create(request,title,acceptance,dependencies), dependencies(task_id,dependencies), claim(task_id), release(task_id,token), block(task_id,token,reason), unblock(task_id,token,reason), submit(task_id,token,evidence), reserve(task_id,token,paths), release_files(task_id,token,reservation), send(request,recipient,body,revision,supersedes), withdraw(message_id), inbox(include_consumed), ack(message_id), evidence(criterion,artifact,revision,kind,passed), usage_report(). Defaults: offset 0, limit 50 (at most 100), include_consumed false, dependencies, revision and supersedes null, release_files false. send's recipient is a member id from op=summary; a retry reuses its request with the same payload; new content needs a new request. Harness ops: summary(since) (since=cursor: unchanged if nothing moved), events(after,limit), usage, reconcile, cancel_run.
Any member may message any other member directly; a question about a task you depend on belongs with that task's owner. task, tasks and summary tasks carry owner_last_activity and owner_state (active, idle after 300 s without a board event, reserved, lost, dead or unknown); an active or idle owner has contact: {"op":"send","request":...,"recipient":"<owner id>","body":...}, any other a recovery note. summary counts carry members_without_claim and members_dead. A worker's evidence op is a proposal; only the coordinator's passed true accepts it. On a wake hint, first use op=summary: if the run is not running, report the summary and do not call inbox or ack; if running, claim ready work (recheck after submit) else yield, and release on a reservation conflict. The inbox, not hints, is authoritative.
Coordinator only: amend(goal,constraints,criteria,reason), verify_task(task_id,token,revision), revalidate_task(task_id,revision,evidence), revoke(task_id,reason) (a claim a member will not finish), recover(task_id,release_files) (after a confirmed death), complete(revision), stop(status,reason). Coordinator: verify artifacts and independent review before accepting evidence or complete; revoke/recover need a running run; a recorded loss pauses the run; read your inbox and ack what you act on; direct members with send, not agent_cmd steer. To wait for the master, block the task and yield; never stop the run. Only the integrator changes branches, commits or integrates the checkout.
