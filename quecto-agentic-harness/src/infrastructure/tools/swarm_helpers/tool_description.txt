Container-only shared swarm workbench. First create a run with goal, constraints, explicit command/review criteria, 1–10 total in-container members (coordinator included), and a Unix wall-clock deadline within seven days. Then establish a fixed pool with existing spawn/agent_cmd; use local spawn inside this shared container. Idle and reserved members count. Never launch nested containers to reset the cap.
Use op=run with exactly one of code/path. Packaged Python: `from swarm import board`; SQLite persists between fresh executions. board.summary(), task_create(request,title,acceptance,dependencies), task(id), dependencies(id,ids), claim(id), block(id,token,reason), submit(id,token,evidence), release(id,token), reserve(id,token,paths), release_files(id,token,reservation), send(request,recipient,body), inbox(), ack(message_id). Evidence entries require artifact and revision. Messages are accepted, then consumed, never implicitly work-completed. Use stable member IDs from summary. Large content belongs in artifacts.
Coordinator only: amend(goal,constraints,criteria,reason), verify_task(id,token,revision), recover(id) after harness-confirmed death, evidence(criterion,artifact,revision,kind,passed), complete(revision), stop(status,reason). Worker evidence is submitted for coordinator review. Empty queues and submitted work do not prove completion. Check artifacts and independent review before accepting evidence at the current revision. Only the designated integrator changes branches, commits, or integrates the shared checkout.
Reservations and helper ownership are cooperative: Bash/arbitrary Python can bypass them. Do not edit the store or call underscore lifecycle methods. Use op=reconcile for confirmed process death, op=summary for readable partial progress, op=cancel_run for parent cancellation. When no work is ready, yield the turn; existing lifecycle notifications are wake hints, the durable inbox is authoritative. Python background jobs use status/output/cancel by job_id. Only a wall-clock run budget is enforced; no exact token cap is claimed.
