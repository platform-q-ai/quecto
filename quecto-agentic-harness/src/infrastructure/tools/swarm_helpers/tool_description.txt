Container-only shared swarm workbench. Read docs {"name":"swarm"} for typed API examples and limits. Default Python RLIMIT_NPROC=1 restricts subprocesses; use the existing bash tool for Git/tests/external commands under its configured policy, and Python for in-process work/board coordination. Do not raise limits from agent code. Workflow is unavailable for every swarm agent: never set workflow, workflow_guards or workflow_spec on worker launches, and an agent running a workflow (guards, bound spec or selected template) cannot create a run; after creation the workflow tool refuses. Ordinary containers that never create a run keep workflow like host-local agents. First create a run with goal, constraints, explicit command/review criteria, 1–10 total in-container members (coordinator included), and a Unix wall-clock deadline within seven days. Then establish a fixed pool with existing spawn/agent_cmd; use local spawn inside this shared container. Idle and reserved members count. Never launch nested containers to reset the cap.
Use op=run with exactly one of code/path. Packaged Python: `from swarm import board`; SQLite persists between fresh executions. board.summary(), task_create(request:str,title:str,acceptance:list[str],dependencies:list[int]), task(id), dependencies(id,ids), claim(id), block(id,token,reason), submit(id,token,evidence), release(id,token), reserve(id,token,paths), release_files(id,token,reservation), send(request:str,recipient:str,body:str), inbox(), ack(message_id). evidence(criterion,artifact,revision,kind,passed:bool) records a proposal from workers with accepted=0; only coordinator passed=True accepts it. Evidence entries require artifact and revision. Messages are accepted, then consumed, never implicitly work-completed. Use stable member IDs from summary. Large content belongs in artifacts.
Coordinator only: amend(goal,constraints,criteria,reason), verify_task(id,token,revision), revalidate_task(id,revision,fresh_evidence) for completed work after later revisions, recover(id) only after confirmed execution-scope death, complete(revision), stop(status,reason). Worker evidence is submitted for coordinator review and immutable under that claim token; identical submit retries are safe. To change submitted evidence, release and reclaim for a new token; do not block a submitted task. Amendments retain full before/after contracts. Empty queues and submitted work do not prove completion. Check artifacts and independent review before accepting evidence at the current revision. Only the designated integrator changes branches, commits, or integrates the shared checkout.
Reservations and helper ownership are cooperative: Bash/arbitrary Python can bypass them. Do not edit the store or call underscore lifecycle methods. Use op=reconcile to detect harness death; unconfirmed surviving execution scopes fail the run and retain ownership, requiring environment disposal, op=summary for readable partial progress, op=cancel_run for parent cancellation. On a wake hint, first use op=summary. If terminal, do not execute Python for inbox/ack; report the summary and remain available for supervisor requests/artifact export. When running but no work is ready, yield the turn; existing lifecycle notifications are wake hints, the durable inbox is authoritative. Terminal settlement cancels foreground and background Python, including coordinator Python: persist final evidence before complete/stop and report from the harness afterward. Artifact retention is per tool instance; export required evidence before cleanup. Python background jobs use status/output/cancel by job_id. Ordinary child processes are terminated when their Python invocation ends, including timeout/drop; background mode does not detach children beyond invocation completion. If operator policy permits subprocesses, wait/join children whose work must finish. Only a wall-clock run budget is enforced; no exact token cap is claimed.

Awaiting master clarification/approval: keep the run running, mark affected tasks with board.block, report the precise question to the master and yield the turn. Do not call board.stop("blocked", ...) to wait for one task: stop and complete end the run as a pause holding that outcome, which only the master (agent_cmd swarm_control resume/close) can lift; members cannot resume it. On a master reply, explicitly acknowledge the decision and act on it before optional inbox work; retain the claim token and submit after completing the approved work. The master uses agent_cmd prompt for idle agents or steer to interrupt a busy coordinator; a transport acceptance is not a coordinator acknowledgment. The deadline keeps running while awaiting input. Never pause the run because one member failed: pause is a whole-run wait; a paused run admits no inference. A member suspended by a provider failure re-arms when the run is resumed, so resume and, only if it stays stuck, steer that member.

Bash build/test commands do not inherit swarm launch identity; use managed spawn for participating agents. Wake hints are checked against current board state before sending but may be stale on arrival. Accepted steering outranks buffered idle work. A control acceptance response means queued, not acted upon; verify handling in the correlated response and transcript.
