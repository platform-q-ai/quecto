# UDS Protocol Capability Matrix

This matrix is the human-facing compatibility map for the UDS protocol. It
summarizes shipped, proposed, deprecated, and removed capabilities so protocol
changes can be reviewed without re-reading every ADR and regression test.

Executable tests remain the source of truth for behaviour. Update this matrix
when a protocol-affecting ADR, issue, or PR lands.

| Capability | Status | Introduced / tracked by | Dependent clients / surfaces | Compatibility and legacy behaviour | Primary tests / scenarios | Notes |
|---|---|---|---|---|---|---|
| Length-prefixed JSON frames | Shipped | [ADR-0008](../architecture-design-records/adr-0008-length-prefixed-uds-framing-and-bounded-events.md), #1059 | TUI, API clients, subagents, external UDS clients | Readers also accept legacy newline-delimited JSON during the compatibility window. Payloads stay JSON per [ADR-0011](../architecture-design-records/adr-0011-stay-json-on-the-wire.md). | `tests/features/uds_framing.feature`; `protocol_shape_tests` | Shared frame bound is `quecto-line-io::PROTOCOL_LINE_CAP_BYTES` (8 MiB). |
| JSON payloads on the wire | Shipped | [ADR-0011](../architecture-design-records/adr-0011-stay-json-on-the-wire.md) | All UDS clients and test harnesses | Binary payload proposals were rejected until a future measurement-driven ADR reopens the decision. | `tests/features/uds_framing.feature`; repo-doc tests | JSON authoring stays at the protocol boundary. |
| Correlation id echoing | Shipped | UDS protocol baseline | Multi-client UDS callers, TUIs, automation | Optional command `id` is echoed on the matching `response`; commands without `id` still receive command-scoped responses. | `tests/features/uds_agent.feature`; UDS dispatch tests | Future typed-id work must serialize as the same string field. |
| Bounded `agent_end` / `turn_end` message references | Shipped | [ADR-0008](../architecture-design-records/adr-0008-length-prefixed-uds-framing-and-bounded-events.md), #1060 | TUI transcript sync, API clients, subagent history forwarding | `agent_end.messages` remains present but empty; consumers use `messageRefs`. | `tests/features/uds_bounded_events.feature`; `protocol_1060_tests` | Prevents large history payloads from being re-emitted in end-of-turn events. |
| Live `get_state` supervision | Shipped | #1282 | Parent agents, TUI, API clients | Reports live execution phase, current/recent tool activity, evidence-based 120-second progress, and canonical in-flight message count. `get_messages` remains stable committed/end-of-turn transcript inspection and may lag while busy. | `tests/features/uds_live_execution_state.feature`; execution-state unit tests | Busy responses retain `snapshot: true` while live fields are overlaid. |
| `get_messages` newest bounded page | Partially shipped / open | #1061 | TUI resume/backfill, API clients, subagent inspection | Omitting `count` returns the newest bounded page, not the full history. `before` pages older history and `hasMoreBefore` reports more pages. Full resume/backfill completion remains tracked as open by ADR-0017. | `tests/features/uds_paged_history.feature`; `tests/repo_docs.rs` | This is the replacement for unbounded history reads; keep compatibility work aligned with the open #1061 tracking row. |
| `get_message` by stable id | Shipped | #1060 | TUI message expansion, recall/spill inspection, API clients | Resolves a single stable id. Very large content is recovered by walking existing `offset` / `nextOffset` / `hasMoreContent` ranged response fields so every serialized response remains bounded. | `protocol_1060_tests`; `uds_dispatch_1093_tests` | Callers should resolve ids from `messageRefs` or paged history entries and continue ranged reads until `hasMoreContent` is false. |
| Spill-store resolution for collapsed refs | Shipped / extending | #1093 | Long-session clients, recall flows, TUI expansion | Collapsed references are resolved from spill storage when available; unresolved refs return explicit errors. | `uds_dispatch_1093_tests`; context/spill tests | Keeps bounded events compatible with durable recall. |
| Child-targeted history forwarding | Shipped | #1060; [ADR-0013](../architecture-design-records/adr-0013-uds-command-family-router.md) proposes hardening | Parent supervisors, `agent_cmd`, subagent monitors | Child-targeted `get_messages`, `get_message`, and `sync` must be forwarded to the child and must not fall through to parent-local history. | Subagent protocol/monitor tests; UDS dispatch forwarding tests | Phase 3 adds a forwarding pre-router to preserve this invariant. |
| `workflow_state` identity-tagged events | Shipped | Workflow v2 / PRD Stage B | TUI workflow views, parent supervisors, subagents | Parent monitors re-emit child workflow state with canonical `agent_id` and `parent_id`; arbitrary child keys are not forwarded. | `tests/features/workflow_event_identity.feature`; workflow UDS tests | Allows a client to rebuild the unit tree from one parent stream. |
| Subagent passive completion notes | Shipped | Subagent notification work; [ADR-0015](../architecture-design-records/adr-0015-subagent-lifecycle-state-machine.md) proposes hardening | Parent agents, API clients, TUI subagent bar | Completion/failure notes are coalesced and surfaced passively; read child output with `agent_cmd get_messages` after the note. | `tests/features/subagent_notify.feature`; `tests/features/agent_cmd_tool.feature` | Phase 4 will model lifecycle transitions explicitly. |
| `get_subagents` live registry snapshot | Shipped | Subagent UDS protocol work; #1378 | Parent agents, TUI, API clients | Returns registry state including parent identity and workflow snapshot when available. `agentId` remains the display label; `agentUuid` is additive hidden durable identity; `displayName` is an additive alias. Clients key durable state by `agentUuid` when present, with legacy `agentId` fallback. Exited children remain visible long enough for result recovery but are not display-label command targets. | `tests/features/subagent.feature`; `tests/features/subagent_protocol.feature`; `tests/features/subagent_monitor.feature` | Complements passive events for reconstructing the unit tree. |
| `set_tool_policy` patch/replace operations | Shipped | #1374 | TUI, API clients, external UDS clients | Legacy callers that omit `operation` keep patch semantics. `operation:"replace"` is additive and requires `unlistedScope`; it applies listed scopes and reconciles every currently registered unlisted tool to the closed-world scope while preserving timing mode behaviour. | `protocol_policy_tests`; registry policy tests; TUI/API set-tool-policy tests | Prefer stable `toolId` over `name`; restriction ceilings still block widening. |
| Extension catalog / reload commands | Shipped | Extension subsystem | Extension authors, operators, test harnesses | Startup-loaded extension surfaces refresh through explicit reload, not filesystem watching. | `tests/features/extensions.feature`; extension tests | See [ADR-0002](../architecture-design-records/adr-0002-reload-trigger-for-startup-loaded-surfaces.md). |
| Dynamic provider registration command | Proposed / deferred | [ADR-0003](../architecture-design-records/adr-0003-uds-register-provider-for-dynamic-model-provider-registration.md) | Future provider-management clients | No shipped `register_provider` UDS behaviour in v1; provider changes use existing config/model reload surfaces. | Runtime model/provider tests | Reserved for a future protocol change. |
| Capability matrix maintenance | Shipped documentation baseline | [ADR-0017](../architecture-design-records/adr-0017-protocol-evolution-matrix.md) | Maintainers and reviewers | Matrix updates are required for protocol-affecting changes; tests still pin executable compatibility. | `tests/repo_docs.rs`; repo-doc BDD | Phase 0 baseline document. |
