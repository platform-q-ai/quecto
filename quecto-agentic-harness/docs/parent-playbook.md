# Parent playbook override

The parent agent uses the bundled repository-root `PARENT_PLAYBOOK.md` by default. To replace **only the parent orchestration playbook**, put a UTF-8 file named `PARENT_PLAYBOOK.md` directly in the agent's initialization directory (`--cwd` when specified; otherwise the process working directory). That file replaces the bundled playbook verbatim, including when empty. Lookup is exact: no ancestor traversal, home/config fallback, or merging. Missing override uses the bundled default; a present file that cannot be read or decoded fails startup with its path rather than silently applying a different policy. Changes take effect on the next agent startup, not during a session. If your custom playbook refers to a project-specific prompt file, give its path relative to the initialization directory (`--cwd` if specified, otherwise the process working directory), and instruct the agent to read that file from there. For example, with `--cwd /path/to/project`, a reference to `docs/my-spike.md` means `/path/to/project/docs/my-spike.md`; the packaged `docs {"name":"spike-prompt"}` page remains available without any project files. The loader does not rewrite or automatically load paths mentioned in custom playbook text.

The parent identity preamble and child ownership preamble are distinct from the playbook. Children do not receive either the parent playbook or its override. `AGENTS.md`, when present in the initialization directory, follows core instructions; the explicit `--system-prompt` follows `AGENTS.md`; extension snippets follow that. These additional prompt sources are additive and do not replace the parent playbook. A spawned child's explicit system prompt is likewise separate from the parent playbook. The disposable investigation template at `quecto-agentic-harness/docs/spike-prompt.md` is not the parent playbook and is not changed by this override.
